# LSM 课程热身轨道

这不是 LSM 的教程。

这是进 LSM 之前的**热身**：五个从零搭的小项目，把你从「能在一张卷子上写对算法的人」变成「能写出一个会掉电、会崩、会有别人同时访问、还不会丢数据的存储程序的人」。

这两件事之间的差距，比大多数人以为的大。竞赛里你的程序从 `main` 开始到 `return 0` 结束，中间不会有人 `kill -9` 它，不会有第二个线程同时动你的数组，更不会有「三个月前写进磁盘的数据现在读不出来」。LSM 的五个阶段全都建立在「这些问题已经会处理」的前提上，所以这里先把它们单独拎出来练一遍。

## 五个轮子

| 轮子 | 做什么 | 大约 |
| --- | --- | --- |
| [轮子 1](01-cli-tool.md) | 命令行笔记工具：`note add/list/search/delete` | 6–8 h |
| [轮子 2](02-persistence.md) | 让 note 记住：二进制格式 + 版本号 + 损坏检测 | 8–10 h |
| [轮子 3](03-index.md) | 索引分层：50 万条时把数据放磁盘、索引留内存 | 10–14 h |
| [轮子 4](04-wal-recovery.md) | 日志恢复：`kill -9` 之后一条不少 | 10–14 h |
| [轮子 5](05-concurrency.md) | 并发与优雅关闭（选做） | 8–12 h |

## 两条路径

**最短路径（30–40 h）**：轮子 1 → 轮子 2 → 轮子 4 → 直接进 LSM 阶段 0–2。

跳过轮子 3 和 5。够用，因为阶段 0–2 的数据量还不至于逼你分层，也没有并发要求。代价是到阶段 3 写 Compact 的时候，你会第一次遇到「数据在磁盘上，我怎么只读一小块」——那时候补也来得及，就是会疼一点。

**完整路径（50–70 h）**：五个轮子全做 → 进 LSM 阶段 0–4。

轮子 3 和 5 不是可选项而是提前交学费：索引分层对应 LSM 的 SSTable + 索引块，并发对应 Compaction 与读写的相互阻塞。先在小项目里被坑一遍，比在大项目里被坑便宜得多。

## 什么时候可以进 LSM

去 [入场券自测](06-entrance-ticket.md) 走一遍。12 道题能答上 9 道、并且能当场跑出对应的现象，就可以进 LSM 了。

答不上来的题不用猜——每题后面都写了回哪个轮子的哪一节。回去补那一个点，比重头再刷一遍整轮快得多。

## 回到主轨

LSM 五阶段在 [https://docs.hanzel.top/lsm/](https://docs.hanzel.top/lsm/)。热身站是它的前置，不是替代。

热身站里的代码不会进 LSM 的仓库，LSM 也不会复用这里的文件格式。这里唯一要带走的东西是：**遇到「存不住 / 崩了 / 抢资源」这类问题时，你知道该往哪儿看。**
