附录：轮子 ↔ OJ 题号映射

附录：轮子 ↔ OJ 题号映射

这一页解决一个问题：热身站里的代码大部分是 IO 和生命周期，没法判题。哪些部分能抽成纯函数、能拿去 OJ 上刷？

判据很简单：一个函数如果只吃字节/数组、只吐字节/数组，不碰文件、不碰线程、不碰时钟，它就能 OJ 化。

映射总表

轮子 可 OJ 化的纯函数 难度 在 LSM 里对应什么 HydroOJ 检索词 无题库时的自测方法
1 · 命令行工具 子串搜索（含重叠匹配） 入门 —— 字符串匹配 KMP 3 组输入输出，必须含 aaa 搜 aa 命中 2 次
1 · 命令行工具 shell 词法切分（引号/转义） 入门 —— 模拟 字符串处理 3 组输入，含未闭合引号，要求报错而非吞掉
2 · 持久化 VarInt 编解码 入门 SSTable 索引块的键/偏移编码 进制转换 位运算 往返 10 万个随机数，decode(encode(x)) == x 全过
2 · 持久化 CRC32 入门 每个 block / 每条 WAL 记录的校验 CRC 哈希 和 zlib 或 cksum 对比 1000 组随机串
2 · 持久化 定长/变长记录流解析 中等 Block 内部记录解析 模拟 字符串处理 3 组含「尾部截断」的输入，要求输出最后完整记录的偏移
3 · 索引分层 二分查找（首个 ≥ x） 入门 SSTable 块内定位、索引块定位 二分 有序表 10 万随机数组 × 1 万次查询，和 lower_bound 全比对
3 · 索引分层 跳表 insert/find/erase 中等 MemTable 的有序结构 跳表 平衡树 20 万次随机操作，和 std::map 结果全比对
3 · 索引分层 静态区间第 K 小 中等 —— （练定位手感） 主席树 整体二分 随机数据暴力对拍
4 · 日志恢复 幂等重放（状态机） 中等 WAL replay 模拟 同一日志重放 1 次 / 2 次 / 10 次，终态必须相同
4 · 日志恢复 带长度前缀的流式扫描 中等 WAL 恢复、Block 扫描 模拟 双指针 构造 3 组：完整 / 尾截断 / 中间坏 CRC
5 · 并发 Bloom filter 中等 减少无效 SSTable 查找 位运算 哈希 10 万插入 + 10 万查询，误判 < 1%，无假阴性，内存 < 1 MB
5 · 并发 SPSC 无锁队列 较难 后台任务投递 队列 模拟 100 万次入队出队，顺序和计数全对
—— （LSM 阶段 2 前置） MergeIterator（多路归并） 中等 多个 SSTable 的有序合并 归并 堆 优先队列 5 路各 10 万有序数据，归并结果和 sort 全比对

用哪几个最划算

如果你只有时间刷三个，选这三个：

  1. VarInt 编解码 + CRC32（轮子 2）—— 一天能写完，而且这两个东西你在 LSM 阶段 2 会直接复用。它们不是练习题，是生产代码的草稿。
  2. 跳表（轮子 3）—— 写一遍你就理解「为什么 LSM 的 MemTable 不用红黑树」。跳表的迭代器天然有序、插入不用旋转，这两点直接决定后面写 MergeIterator 有多痛苦。
  3. MergeIterator（多路归并 + 堆）—— 这是 LSM 阶段 2 的核心组件。在这里先写一个纯内存版（vector<vector<int>> 归并），到 LSM 里换成「每个 SSTable 一个迭代器」，逻辑一行不用改。

一个提醒

OJ 判题只看输入输出，不看你的错误处理。而热身站里最值钱的部分恰恰是错误处理（坏文件、半条记录、kill -9）。

所以：OJ 用来练纯函数的正确性和速度，错误处理只能靠自己写自测。 每个纯函数配一条「坏输入」用例，比如 VarInt 的截断字节串、CRC 覆盖范围错一位、归并时某一路提前耗尽 —— 这三条比刷十道模板题有用。

自测脚本模板

放在项目根的 test.sh，每轮结束时跑一遍：

#!/usr/bin/env bash
set -u
fail=0
check() {  # check <名字> <期望> <实际>
  if [ "$2" = "$3" ]; then echo "  ok   $1"
  else echo "  FAIL $1: 期望[$2] 实际[$3]"; fail=1; fi
}

check "空输入返回空" "0" "$(./build/note list | wc -l | tr -d ' ')"
./build/note add "abc" > /dev/null
check "add 之后有一条" "1" "$(./build/note list | wc -l | tr -d ' ')"
check "子串匹配" "1" "$(./build/note search bc | wc -l | tr -d ' ')"
check "删不存在的 id 报错" "1" "$(./build/note delete 999 >/dev/null 2>&1; echo $?)"

[ $fail -eq 0 ] && echo "ALL PASS" || { echo "HAS FAILURE"; exit 1; }

好处是：改完代码跑一次，比手工敲五条命令可靠。这个习惯在 LSM 里会救你很多次 —— 那边的状态更多，手工验证根本不可能覆盖。
